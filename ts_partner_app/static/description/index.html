How a Renewal Actually Flows Through It

01 · Reminder Fires

Expiry date is hit — the responsible user gets an activity, an email, and a chatter note. Missed cron runs still catch up, since the check keys off expiry_date <= today plus a notified flag rather than an exact date match.

02 · Quote in One Click

"Create Renewal Quote" drafts a Sale Order pre-filled with the client's monthly billing amount — nothing to re-type.

03 · Client Confirms

Standard Odoo quotation flow — nothing new for the client or your sales team to learn.

04 · Dates Extend Themselves

On confirmation, the asset's end date pushes out by its renewal period and the stage resets to Running — automatically.

Built for People Who'll Read the Code

Encryption, not obfuscation

Passwords and access tokens are Fernet-encrypted with a key derived from your database's own secret. The database column holds ciphertext; the field you see is a non-stored compute.

Every reveal is logged

Clicking the eye icon or editing a credential writes a row to the access log: user, action, field, timestamp. Managers can audit exactly who saw what.

Real TLS, not a ping

The health check opens an actual socket, negotiates TLS where applicable, and reads the certificate's real expiry — it doesn't trust a status API.

Catch-up safe crons

Expiry checks key off expiry_date <= today plus a notified flag, not "today equals expiry date" — a missed nightly run doesn't silently skip a client.

    compute='_compute_password',
    inverse='_inverse_password',
    groups='ts_partner_app.group_partner_asset_manager',

def _inverse_password(self):
    for rec in self:
        rec.password_encrypted = rec._encrypt_value(rec.password)
    self._log_credential_action('update', 'password')
