Why it exists

Client infrastructure lives in a dozen tabs. This puts it in one.

Between browser bookmarks, a spreadsheet of server logins, and a shared notes doc, most Odoo partners already track this — just nowhere near their actual CRM. Odoo Clients 360 keeps every domain, server, Odoo login, and GitHub repo attached to the customer record you already work from, with the credentials encrypted, the renewals automated, and billing — one-off or recurring — started from the same record.

Under the hood

Built for people who'll read the code

Your buyers are Odoo partners. Here's what actually happens when a credential is saved or a health check runs.

01

Encryption, not obfuscation

Passwords and access tokens are Fernet-encrypted with a key derived from your database's own secret. The database column holds ciphertext; the field you see is a non-stored compute.

02

Every reveal is logged

Clicking the eye icon or editing a credential writes a row to the access log: user, action, field, timestamp. Managers can audit exactly who saw what.

03

Real TLS, not a ping

The health check opens an actual socket, negotiates TLS where applicable, and reads the certificate's real expiry — it doesn't trust a status API.

04

Catch-up safe crons

Expiry checks key off expiry_date <= today plus a notified flag, not "today equals expiry date" — a missed nightly run doesn't silently skip a client.
