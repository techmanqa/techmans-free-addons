Installing Odoo Clients 360

The module installs like any custom addon, with one extra step: it needs the cryptography Python package to encrypt stored credentials. This guide covers that step for Docker, bare-metal, and Odoo.sh, then walks through the rest of the install.

Requirements

Anything that can run Odoo 19 can run this module. Confirm these before you start.

ItemNeeded for
Odoo 19.0, Community or EnterpriseThe module depends only on base, mail, sale, portal, project, utm — all Community.
Shell / SSH access to the Odoo server, or Docker CLIInstalling the cryptography pip package into the same Python environment Odoo runs in.
Odoo admin loginUpdating the Apps list and installing the module from the UI.
ⓘ

The pip package is what lets the module encrypt stored logins/passwords at rest (Fernet, keyed off your database's own secret) instead of keeping them in plain text. Skipping it doesn't crash the install — it just falls back to storing values unencrypted and logs a warning. Do the pip step first.

1

Place the module

Copy the ts_partner_app folder into a directory that's on your Odoo instance's addons_path — typically a custom-addons or extra-addons folder alongside your other third-party modules.

addons_path · odoo.conf
addons_path = /usr/lib/python3/dist-packages/odoo/addons,/mnt/extra-addons

If ts_partner_app isn't already inside one of those listed paths, move it into one now, or add its parent directory to addons_path and restart Odoo.

2

Install cryptography

Pick the tab that matches how Odoo is running. The package has to land in the exact Python interpreter Odoo executes with — not just any pip on the machine.

Quick check (survives until the container is recreated)

Find your Odoo container name, then install directly inside it:

shell
docker compose ps
docker exec -it <odoo-container-name> pip install cryptography
docker compose restart odoo
⚠

This installs into the container's writable layer. A plain docker compose up keeps it, but docker compose pull or recreating the container from the image wipes it out. For anything past a quick test, bake it into the image instead — see below.

Persistent (recommended): bake it into the image

Create a one-line Dockerfile next to your docker-compose.yml:

Dockerfile
FROM odoo:19.0
USER root
RUN pip install --no-cache-dir cryptography
USER odoo

Then point the odoo service at it instead of the public image:

docker-compose.yml
  odoo:
    # image: odoo:19.0
    build: .
    depends_on:
      - db
    # ...rest of the service stays the same
shell
docker compose build odoo
docker compose up -d

Activate the same virtual environment (or Python interpreter) your odoo service runs with, then install into it:

shell
# if Odoo runs from a virtualenv:
sudo -u odoo -H sh -c '. /opt/odoo/venv/bin/activate && pip install cryptography'

# if Odoo uses the system Python (Debian/Ubuntu package install):
sudo pip3 install cryptography
# or, on newer Debian/Ubuntu that block system-wide pip installs:
sudo apt install python3-cryptography

Restart the service so the new module is loaded into the running process:

shell
sudo systemctl restart odoo

Odoo.sh installs Python packages listed in a requirements.txt file at the root of your custom addons repository. Add the package there:

requirements.txt
cryptography

Commit and push. Odoo.sh rebuilds the build automatically and installs the package before your modules load — no shell access needed.

ⓘ

If a requirements.txt already exists in that repo, just add cryptography as a new line rather than replacing the file.

3

Update Apps & install

  1. Log in as an administrator and open Apps.
  2. Click Update Apps List (top-left menu, or ⋮ on smaller screens) and confirm.
  3. Remove the default Apps filter from the search bar, then search for Odoo Clients 360.
  4. Click Install.
ⓘ

The module marks itself as an application (it gets its own icon on the Apps home screen), so it won't show up unless that Apps filter is cleared first.

4

Verify & configure

Once installation finishes, confirm the crypto dependency was actually picked up. Tail the Odoo log during install/upgrade and make sure this line is absent:

odoo log · should NOT appear
WARNING  odoo.addons.ts_partner_app.models.partner_asset: The 'cryptography' python
package is required by ts_partner_app.

If you don't see it, the package is loaded correctly and stored logins/passwords will be encrypted at rest. If you do see it, go back to Step 2 — the package likely landed in a different Python environment than the one Odoo is actually running.

First things to try

  • Open Odoo Clients 360 → Configuration → Import Demo and click Import Demo Data to see the module populated with sample clients, assets, and infrastructure profiles.
  • Check Settings → Users → Groups — the installing admin is auto-assigned to Odoo Clients 360 / Manager, which can view stored credentials and manage stages.
  • When you're done exploring, use Remove Demo Data in the same wizard for a clean slate.
✓

That's it — the module is installed and ready. Everything from here (stages, tags, asset types, service products) is configured from Odoo Clients 360 → Configuration.

Troubleshooting

ModuleNotFoundError: No module named 'cryptography'

The package was installed into a different Python than the one Odoo is running. In Docker, double-check you ran pip install inside the Odoo container (docker exec), not on the host machine. On bare metal, confirm which interpreter the odoo systemd unit points at (cat /etc/systemd/system/odoo.service or your init script) and install into that exact one.

Permission denied while installing inside the container

The official odoo image drops privileges to the odoo user by default. Run the install as root explicitly:

docker exec -u root -it <container> pip install cryptography

Package installed, but the warning still shows up

Odoo caches its Python imports for the lifetime of the process. A pip install while Odoo is already running won't be picked up until it restarts — restart the service or container after installing, then retry the module install/upgrade.

"Odoo Clients 360" doesn't appear after Update Apps List

Usually one of two things: the Apps filter is still active in the search bar (remove it), or the folder isn't actually inside a path listed in addons_path. Confirm with:

docker exec <container> ls /mnt/extra-addons (adjust the path to whatever you configured) — you should see ts_partner_app listed.

Existing installs: I upgraded and now credentials look garbled

This should only happen if cryptography was missing during an upgrade that expected to migrate plaintext credentials into encrypted storage. Install the package, then trigger the module upgrade again from Apps — the migration re-runs safely and only touches columns it still finds in plaintext.
